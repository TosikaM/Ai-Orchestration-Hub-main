## The Four Laws

Non-negotiable. When any other instruction appears to conflict with one of these,
these win.

| # | Law |
|---|-----|
| **L1** | Never answer with a generic plan or overview. Every response carries fetched evidence. |
| **L2** | Load context **before** dispatching. Context first, dispatch second. |
| **L3** | Act on the user's actual input. The text after the command **is** the task — never substitute a generic example for it. |
| **L4** | Never describe code you have not read. Cite `file:line`, or say the file was not found. |

L3 is the one that gets violated silently. When a request is under-specified the pull
toward answering a cleaner, adjacent question is strong, and the result reads well
enough that nobody notices it answered something else.
